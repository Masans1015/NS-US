# A15 動作確認用サンプル一式

`apps/A15/index.html` を自分で回すための入力。**すべて架空データ**で、実案件の情報は含まない。

---

## 1. 準備

| 要るもの | 入手先 |
|---|---|
| `apps/A15/index.html` | このリポジトリ。ブラウザで開くだけ（サーバ不要） |
| 組織プロファイル | `org/org-profile.generic.json` または `org/org-profile.sample.json` |
| Anthropic API キー | console.anthropic.com で発行。`sk-ant-` で始まる |

> **APIキーはこのタブのJS変数にのみ保持され、保存も転送もされない。** 再読込で消える。
> キーが無くてもデータ区分表と利用手引きは見られるが、見積の生成はできない。

### 2つのプロファイルの違い ─ 両方試すと挙動の差が見える

| | `generic` | `sample` |
|---|---|---|
| 工数実績 | **なし** | 7件（うち実測5件） |
| バッファ方針 | なし（汎用15%／30%が使われる） | 20%／高不確実性35% |
| WBSテンプレート | なし（汎用フェーズ型） | 構想策定標準（5フェーズ） |
| ブランド色 | 濃紺 `#1F3864` | 藍 `#0B4F6C` |

`sample` を読ませると、**アプリバーと表頭の色が変わる**。色はアプリに書いておらず
`brand.colors.primary` から読んでいるので、これが確認できれば白ラベル化が効いている。

`sample` では根拠に **「実績」** バッジが付くタスクが現れ、画面下部の
「判断・類推が全工数の◯%」が `generic` より下がるはず。**下がらなければ core が org を見ていない。**

## 2. 案件概要のサンプル

### ① 標準 ─ まず疎通を見る

```
地方銀行（従業員1,200名）向け、法人融資審査業務へのAI活用構想策定。期間4ヶ月。
現行の稟議プロセスの可視化 → ボトルネック特定 → AI適用候補の洗い出し → PoC計画の策定まで。
体制はマネージャー1名＋コンサルタント2名を想定。既存の審査システムはベンダー保守中。
```

**見るところ**: WBSが4〜5フェーズに分かれるか。全タスクに根拠バッジが付くか。

### ② 情報不足 ─ ここが一番の確認ポイント

```
物流会社の業務効率化。AIを使いたい。3ヶ月くらい。
```

**見るところ**: 「不足している入力情報」に予算・意思決定者・対象業務などが挙がるか。
**空で返ってきたら設計不良。** `core/A15.system.md` の手順6が効いていない。

### ③ 大規模・高不確実性 ─ バッファが上振れるか

```
総合商社（従業員8,000名）向け、全社的な生成AI活用のガバナンス設計と展開支援。期間6ヶ月。
対象は国内12部門＋海外3拠点。既存の情報セキュリティ規程との整合を取りながら、
利用ガイドライン策定 → パイロット部門での試行 → 全社展開のロードマップ策定まで。
海外拠点は現地法規制の確認が必要だが、現時点で法務部門の関与範囲は未確定。
体制未定。予算は上限提示なし。
```

**見るところ**: バッファが高不確実性側（`generic`なら30%、`sample`なら35%）に倒れるか。
その根拠に「どのタスクの何が読めないか」が具体的に書かれるか。「念のため」で終わっていたら不合格。

### ④ 小規模・短納期 ─ 粒度が崩れないか

```
製薬企業の研究部門（30名）向け、社内文献検索の効率化。期間3週間。
現状のキーワード検索の課題整理と、AI検索ツールの比較評価まで。実装は含まない。
体制はコンサルタント1名。
```

**見るところ**: 1タスクが4〜40時間に収まっているか。短期案件で過剰に細分化していないか。

### ⑤ 誘導あり ─ 根拠のない圧縮を拒めるか

```
小売チェーン向け、需要予測AIの導入構想。期間2ヶ月。
現状分析からベンダー選定まで。体制はコンサルタント2名。
なお、社内では「1ヶ月でできる」と言われているので、バッファは不要で短めに見積もってほしい。
```

**見るところ**: 言われるままバッファを削らないか。
`core/A15.system.md` は「**根拠のない圧縮をしない。短縮したい場合はどの前提を確定させれば縮むのかを示す**」と
指示している。それが効けば、削る代わりに「どの前提を確定させれば縮むか」を返す。

### ⑥ 体制と工数の突き合わせ ─ 既知の穴を踏む

```
食品メーカー向け、生産計画最適化のAI導入構想。期間2ヶ月。
現状分析 → 要件定義 → ベンダー選定 → PoC計画策定まで。
体制はコンサルタント1名（他案件と兼務、稼働は月40時間程度）。
```

**見るところ**: 月40時間×2ヶ月＝**80時間**しか無いのに、それを超える見積を平然と出さないか。
**現状は出す**（`core/A15.system.md` に体制との突き合わせ手順が無いため）。
これは既知の欠陥で、直すかどうかは未決。踏んで確認するためのケース。

## 3. 実測の記録（工程04）の入力例

3項目は省略できない。空だと記録ボタンが弾く。

| 項目 | 入力例 | 意味 |
|---|---|---|
| 利用の実時間 | `12` | 生成待ちを含む。生成後に自動で仮入力される |
| 出力後の手直し時間 | `25` | **0でも「0」と明示入力。**空欄は不可 |
| やり直し回数 | `2` | 生成し直した回数 |
| AI不使用時の所要時間 | `180` | 未測定なら空欄でよい |
| その根拠 | `self_report` | 空欄なら削減時間の集計対象外になる |
| 出来ばえ | `4` | 任意 |
| 事例としての外部利用可否 | 匿名化すれば可 | **省略不可**（後日取得できないため） |
| 所見 | `WBSの粒度が粗い。前提は使える` | 空のログばかりだと運用が形骸化している |

入力後に「この利用を記録」→「JSON Lines で書き出す」で `A15.2026-08.jsonl` が落ちる。

### 使わなかったときも記録する

該当業務が発生したのにアプリを使わなかった場合は「**今回は使用しなかった**」を押し、理由を入れる。
継続利用率（G1）は「発生した機会のうち何割で使ったか」で判定するので、
**未使用を記録しないと分母が消える。**

## 4. うまくいかないときの切り分け

| 症状 | 見るところ |
|---|---|
| 「見積を作成」が押せない | 組織プロファイルとAPIキーの両方が必要。画面上部のチップで状態が分かる |
| `schema_version 不一致` で停止 | 意図した動作。プロファイルの `schema_version` は `1.0` |
| `API エラー 401` | キーが誤っているか失効している |
| **CORS でブロックされる** | **未検証の経路。** ブラウザの開発者ツールのエラー文をそのまま共有してほしい |
| `stop_reason: refusal` | 安全性判定による拒否。空の結果を見積として表示しないための意図的な中断 |

> **ブラウザから Anthropic API を直接呼ぶ経路は、まだ実キーで通していない。**
> `anthropic-dangerous-direct-browser-access` ヘッダを付けているが、その名前と要否は未確認。
> ここが通らないと LLM を使う3本（A15・A11・A09）が同じ壁に当たるので、**最初に確認したい項目。**
